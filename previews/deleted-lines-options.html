Branch Review Gutters · design options

Reviewing deleted code in the editor

You want a GitHub-style review of the branch, but done in VS Code so you can Ctrl+click, Find References and Find Implementations while you read. Your refactor deletes a lot, so the deleted lines and deleted files need to be visible too. Below, each option is mocked on the same example change: notify() stops calling SmsClient directly and goes through a new ChannelRouter, and src/sms/client.ts is deleted.

Option A · closest to GitHub's "Files changed"

Branch changes in one scrolling tab

VS Code has a built-in multi-file diff editor (the one Source Control uses for "View Changes"). The extension can open it with every file from your branch compared against the base, using the vscode.changes command. Each file is a real inline diff editor stacked one after another, and deleted files appear as all-red sections.

Branch changes vs main14 filesmulti-diff

Works well

  • Deleted lines are full red rows, added lines green, like GitHub.
  • Deleted files show in the same scroll, so nothing is hidden.
  • Ctrl+click, Find References and Find Implementations work on new and unchanged code, because that side is your real file.
  • Small to build: the extension already knows the change set and base URIs.

Limits

  • You can't put the cursor on a red line, so you can't Ctrl+click a deleted call.
  • It's a diff tab, not your normal editor. Opening a definition jumps to a normal tab.
Option B · one file at a time

Inline diff for the current file

The same view as A, but for one file. "Compare with Base" already opens a side-by-side diff. A new "Compare with Base (Inline)" command would open it as a single column. You can still type in it.

notify.ts(base ↔ working tree)inline

Works well

  • Same full red and green rows as A.
  • Full IDE features on the code that exists now.
  • You can edit the file while reviewing it.

Limits

  • Red lines can't be clicked into, same as A.
  • VS Code has no option to open one diff inline. The command has to switch the diffEditor.renderSideBySide setting, which also changes your other diffs.
Option C · for deleted files

Deleted file, shown red from top to bottom

Opening a deleted file from the Changed Files view already shows its base version. This option adds a banner and paints every line red so you can't mistake it for live code. This works because the extension can colour lines that exist, and here every line exists in the base version.

client.tssrc/sms · base versionread-only
Deleted on this branch. You're viewing it as it was at main (a1c9e04).

Works well

  • Read the whole deleted file with normal syntax colours, search and selection.
  • Mark it seen like any other file.

Limits

  • Go to Definition is limited. The file only exists in git, so the language server treats it as a loose file. Jumps within the file usually work; jumps into other files depend on the language.
  • Find References won't find callers of the deleted code, because those calls are deleted too. Option A shows where they went.
Option D · stay in the normal editor

Hover to see what was removed

Your normal editor, with a red marker in the gutter between lines where code was removed. Hovering it shows the removed lines.

notify.tssrc

Works well

  • Every IDE feature works, since this is the normal editor.
  • The file doesn't move around while you edit.

Limits

  • You only see deleted lines if you hover. Easy to miss in a big refactor.
  • Not much better than the click-to-peek you already have from the gutter markers.
Option E · stay in the normal editor

Faint note at the end of the line

Same normal editor, with faded red text after the line where the removal happened, so you notice it without hovering. It can only show one line.

notify.tssrc

Works well

  • Always visible, every IDE feature still works.

Limits

  • Only a one-line summary. You still need hover or a diff to read the removed code.
  • Gets noisy in files where most lines changed.

Suggested combination

  1. A as the main review mode: one command, "Review Branch Changes", opens every changed file in one scrolling tab, deleted files included.
  2. B for when you're in a single file and want its deleted lines without opening the whole branch.
  3. C so a deleted file opened from the Changed Files view is unmistakably deleted.

D and E are possible later, but they don't show deleted code as clearly as A and B.
